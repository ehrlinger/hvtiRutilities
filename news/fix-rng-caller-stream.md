* `generate_survival_data()` and `cache_fit()` no longer save, restore or remove `.Random.seed` in the global environment, which the CRAN Cookbook forbids. Each now calls `set.seed()` only when it is given a seed.
  * `generate_survival_data(seed = NULL)` used to call `set.seed(NULL)`, which reseeds from the clock. It now sets no seed and draws from the caller's stream, so `set.seed(s); generate_survival_data(seed = NULL)` gives the same data as `generate_survival_data(seed = s)`. The default stays `seed = 1024`.
  * After a seeded `generate_survival_data()` call, the stream is left where the simulation ended rather than put back as it was.
  * A seeded `cache_fit()` calls `set.seed(seed)` before the computation and again after it (even when it fails), and once on a cache hit. If the computation changes the generator with `RNGkind()`, the caller's kinds are put back before that second call. Computed and loaded results therefore leave the stream in the same state, so code after the call draws the same numbers whether or not the cache was hit. It used `withr::with_seed()`, which restored the caller's stream. An unseeded `cache_fit()` is unchanged: it draws from the caller's stream and warns if the computation used random numbers.
  * Code that relied on either function leaving the stream as it found it should set its own seed before its next random step. The hvtiRtemplates templates already seed every random call where it runs.
