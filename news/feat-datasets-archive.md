* `update_manifest()` now moves the registered version it replaces into `datasets/_archive/`, with its `.schema.csv` and build record, so only the current version sits beside the source. `built_20261021.parquet`, `built_20261021_r2.parquet` and their schema files no longer pile up in `datasets/`; Quarto skips `_archive/` as it skips every folder starting with `_`, the convention `hvtiRtemplates::upgrade_job()` uses for a job's backups. `manifest.yaml` is unchanged: it records bare names, and `verify_manifest()` finds each earlier version beside the source or in `_archive/` and checks it by SHA-256 as before. `read_built()` does the same, so a `manifest.yaml` restored from version control to reproduce an earlier version still reads it after a later registration archived it. A version file that is a symlink, or that another registered dataset reads as its source (a version's schema registered as a dictionary, say), stays beside the source. A study registered before this release needs no migration; its next registration moves every earlier version still beside the source. A move that fails, because a file of that name is already in `_archive/`, leaves the file where it is with a warning, and a new version never takes a name already in `_archive/`. Verify an archived study with this release or later: an older `verify_manifest()` looks only beside the source and reports the archived versions as missing.
