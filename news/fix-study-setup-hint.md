* New `study_verify()` and `study_recover()` run the qhsprograms `study-setup --verify` and `study-setup --recover` from R on the LRI servers, so a user never has to leave the R console for them. `study_verify()` loads the Study Tracker credentials into that command's process only; R never reads them. `study_recover()` shows a dry run first and writes only with consent: a yes to its question, or `yes = TRUE`; a non-interactive call without it writes nothing. Both stop with a plain reason off the LRI servers or, for `study_verify()`, without a credentials file. Verification against Study Tracker and recovery from CORR_STUDIES are planned and not live yet.
* `study_config()`, `study_status()` and a checkpoint left unpushed for an unverified identity now point to `study_verify()` and `study_recover()` instead of the `study-setup` shell command. A user who followed the old hint on the LRI servers got only `command not found`.
